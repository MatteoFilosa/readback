ReadBack

Helps doctors and hospital teams find the patients they need by describing them in their own words. Every filter the model sets is read back and checked, and nothing runs until a clinician presses Run.

        Why ReadBack
        
      
    
        
    
        In a hospital, a verbal order is read back before anyone acts on it: the
      receiver repeats it, the sender confirms. ReadBack applies the same rule to the questions
      clinicians ask of patient data.
        

    
        The problem
        
    
        Finding a cohort, say women over 65 with diabetes in the North-West, admitted last
      year, means waiting for an analyst or working through a filter panel with dozens of
      attributes and hundreds of codes. A language model writes the query in seconds, but it can be
      wrong in ways that look right: "and" read as "or", a threshold nobody asked for, a disease
      quietly dropped. For a study, an audit or a recall, a wrong list that looks right is worse
      than no list.
        

    
        What is different
        
    
          
      
        • It targets the error that matters. Text-to-query tools report how often
        the model is right. ReadBack targets the residual: wrong filters that reach the
        clinician with nothing on screen saying so. A wrong filter that is marked costs a second
        look; an unmarked one ends up in the study.
          • 
      
        • The model proposes, code verifies. The model only fills the filter panel.
        It never writes SQL and never sees a patient record. Nine deterministic checks compare the
        request, the filters and the catalog; no second model judges the first, and all nine take
        about a millisecond.
          • 
      
        • The explanation is not generated. Every filter shows the words
        it comes from and spells out its groups ("Sud = these 6 regions", "1 of 4 endocrine
        conditions"), built from the panel and the catalog, so the explanation itself cannot
        hallucinate.
          • 
      
        • The panel stays in charge. Clinicians keep the tool they know: the model
        fills it, they correct it with a click or a new sentence.
          • 
    
        

    
        The residual, measured
        
    
        23 requests, each written in English and in Italian, drafted by six open models on AMD GPUs
      (AMD Token Factory), 46 drafts per model.
        
    
        
    
        Accuracy follows the model, from 25 to 45 of 46. The residual does not: 0 of 46 for every
      model, with a 95% upper bound of 7.7%. A smaller model leaves more to read, not more to
      miss. These requests are the ones the checks were built on, including three gaps the 2B
      model exposed; a held-out set is the next step.
        

    
        How it works
        
    
          
      
        1. Ask in your own words, in any language.
          2. 
      
        2. The model sets the filters on the panel; the ones it moved are outlined.
          3. 
      
        3. Every filter is read back with the words it comes from, highlighted in
        the request, and the checks mark what does not add up.
          4. 
      
        4. Fix or accept each filter. The SQL is compiled by the app and shown.
          5. 
      
        5. Press Run. The result shows how each filter narrows the cohort, so one
        that removes no one, or everyone, stands out.
          6. 
    
        

    
        Reading the screen
        
    
          
      
        • Outlined in magenta: set by the model in the last draft.
          • 
      
        • From the request rests on words of the request.
          • 
      
        • Assumed a value nobody wrote, such as 65 for "elderly". Confirm or edit.
          • 
      
        • Check a warning to read, such as "and" read as "any of".
          • 
      
        • Fix before Run an error that blocks the query.
          • 
      
        • Set by hand your own choice, not compared with the request.

        For clinicians
        
        
          
          
        • A cohort from a sentence, without learning the panel or opening a ticket with the
            data team.
          • 
          
        • The model's guesses in plain sight: a threshold for "elderly", a period for "last
            summer", a whole region for a city.
          • 
          
        • Any language: the request can be Italian or French, the filters and the checks are
            the same.
          • 
        
        
      
        
      
        
        
        For hospitals
        
        
          
          
        • Records stay inside: the model sees the request and the catalog, and the same open
            weights fit a single AMD Instinct MI300X on site.
          • 
          
        • Every draft and every run is logged, including whether the clinician changed the
            filters before running.
          • 
          
        • Codes and places live in plain catalog files: another coding system or country means
            replacing them, not the code.
          • 
        
        
      
        
    
        

    
        Answering the Health and Wellbeing brief
        
    
          
      
        • Uncertainty is visible. Every value nobody wrote is marked Assumed, every
        doubtful reading is marked Check, on the filter it concerns.
          • 
      
        • It knows when a human is needed. Errors block Run, and nothing runs until
        a clinician presses it.
          • 
      
        • No autonomous decisions. It selects patients from criteria a person has
        accepted. It does not diagnose, rank or recommend.
          • 
      
        • Sensitive data handled with care. No patient record reaches the model;
        weights can run on the hospital's own AMD hardware; every patient in this demo is
        synthetic.
          • 
      
        • Measurable improvement. The residual is a number, recomputed offline on
        recorded drafts whenever a check changes, at no inference cost.
